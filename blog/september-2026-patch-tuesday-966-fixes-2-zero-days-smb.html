September 2026 Patch Tuesday: 966 Fixes, 2 Zero-Days, and What a Small Business Needs to Do

TL;DR: the largest release ever, two exploited zero-days, and neither is the scary kind

Microsoft's September 2026 Patch Tuesday fixes 966 vulnerabilities, the largest release in the history of Patch Tuesday, including two zero-days already being used in real attacks.

  • What dropped: 966 fixes by BleepingComputer's count, 105 rated Critical (81 of those remote code execution), released today at 10 AM Pacific. Roughly 2.4 times August's 400, and well past July's previous record of 570.
  • What matters most, and why it is not the headline: both zero-days, CVE-2026-85880 in Windows Advanced Local Procedure Call and CVE-2026-81963 in the Windows Update Stack, are local elevation of privilege at CVSS 7.8, rated Important rather than Critical. Neither gets an attacker in. Both are what an attacker reaches for once phishing has already worked.
  • The one your people can trigger: CVE-2026-69678, a Critical use-after-free in PowerPoint at CVSS 8.8, where Microsoft's advisory confirms the preview pane is an attack vector. Nobody has to open the file.

This week:

  1. Install this month's cumulative updates everywhere and reboot. That single step covers both exploited zero-days.
  2. Patch Windows servers running the DNS role or Remote Desktop Services next. Both take unauthenticated CVSS 9.8 fixes.
  3. Confirm remaining Windows 10 machines are enrolled in Extended Security Updates, and that nobody works all day as a local administrator.

This continues the August 2026 Patch Tuesday post; the managed IT page covers how we run patching so it is verified, not just hoped.

Microsoft shipped its monthly security updates today at 10 AM Pacific, and this is the largest Patch Tuesday ever shipped, by a wide margin, per BleepingComputer's September 2026 roundup. Two of the flaws are already being used by attackers. Here is what is in it, why the honest story is not the number, and how to sequence the work.

What Patch Tuesday is and how it works

On the second Tuesday of every month, Microsoft releases fixes for security flaws in Windows, Office, and its server products. Batching them into one predictable day lets IT teams plan testing instead of rebooting machines at random all month. A home computer takes these whenever Windows decides to install them. A managed business computer takes them through an RMM, short for remote monitoring and management, on a schedule, with per-machine verification that the patch installed and the reboot completed.

Why 2026 broke the model

Until this year, Microsoft had never fixed more than about 200 flaws in a single month. Then AI-assisted bug-finding tools came of age and researchers on every side started using them, a dynamic we covered when an AI model found 271 vulnerabilities in Firefox. June 2026 set a record near 200, July shattered it with 570, August landed at 400, and September has now nearly doubled the old record in one step.

The mechanism has not changed since July, it has just compounded, and the same tooling helps attackers turn a published patch into a working exploit faster than ever. Microsoft rewrote its own deployment guidance in response: deferral periods under three days, deadlines of zero or one day, a grace period of no more than two. Monthly patching is now a process with an owner and a verification step, not a checkbox someone gets to when there is time.

September 2026 by the numbers

This month's release fixes 966 vulnerabilities by BleepingComputer's count, which we use because they count only the CVEs Microsoft published on release day. Other outlets report 972 to 995, because Microsoft's Security Update Guide changed format in July 2026 and no longer publishes one simple list, so each outlet counts differently. The Zero Day Initiative tallies 972 new CVEs with 114 Critical by its own severity math, SecurityWeek reports 974, several outlets land on 973 with 113 Critical, and Action1 counts 995 with 121 Critical. Every source agrees it is the biggest release on record. The 966 also excludes 204 cloud-service flaws Microsoft fixed earlier this month, handled server-side and needing nothing from you.

By Microsoft's ratings, 105 are Critical: 81 remote code execution, 20 elevation of privilege, 2 information disclosure, and 1 security feature bypass. By class, the release is 438 elevation-of-privilege flaws, 258 remote-code-execution, 173 information-disclosure, 56 denial-of-service, 19 security-feature-bypass, and 16 spoofing. The Zero Day Initiative flags 20 of the RCEs as potentially wormable: unauthenticated, no user interaction, the kind malware can use to spread on its own.

By product, per Microsoft's release notes as tallied by SecurityWeek: 723 in Windows, 222 across Office with 111 in Office 2016 alone, 62 in SQL Server, 22 in developer tools, 16 in SharePoint Server, and 9 in Exchange Server.

Both zero-days are the quiet kind, and that is the story

A record release with two actively exploited zero-days reads like a five-alarm month. Read the two flaws and the picture changes. Neither is remote code execution. Both are local elevation of privilege, both CVSS 7.8, and Microsoft rates both Important rather than Critical, marking both as exploited and neither as publicly disclosed.

  • CVE-2026-85880, a heap buffer overflow in Windows Advanced Local Procedure Call. ALPC is the internal plumbing Windows components use to talk to each other. An attacker already running code inside a low-privilege AppContainer sandbox can escape it and elevate to SYSTEM with no user interaction. Reported by researchers at Volexity and Proofpoint. Tenable's Satnam Narang notes Microsoft has not patched an ALPC flaw since April 2023, and that this is only the second ALPC zero-day in nearly four years.
  • CVE-2026-81963, improper link resolution in the Windows Update Stack. A link-following flaw, the same class as the LegacyHive bug patched in August: by abusing how a privileged service resolves a link before touching a file, a local user tricks that service into acting on a file it should never touch, and ends up at SYSTEM. The affected component is the machinery that installs Windows updates, which runs at the highest privilege by design. Credited to Romain Deperne and the Microsoft Threat Intelligence Center, with exploitability listed as functional.

The lesson is not that these are harmless. It is the opposite: this is what the second half of an attack looks like, and it is the half that decides how bad the incident gets. Nobody exploits a local privilege escalation bug from the internet. They exploit it after a user typed credentials into a fake login page, after a document ran a macro, after a stolen session token got replayed. Once an attacker has code running as a normal user, an escalation zero-day turns a contained problem into a full one, because SYSTEM privileges are what let them disable security tooling, read every share, and push ransomware everywhere at once.

So the work beyond the patch is identity and privilege. Phishing-resistant multi-factor authentication stops the foothold, covered in the identity hardening post. Not running as a local administrator all day limits what a foothold can reach, which the privileged access post covers. Managed detection and response with a 24/7 SOC catches the escalation attempt itself, exactly what antivirus alone tends to miss, a distinction drawn in the EDR versus antivirus post.

The PowerPoint bug is the one where behavior changes the outcome

CVE-2026-69678 is a use-after-free flaw in PowerPoint, rated Critical at CVSS 8.8. A use-after-free is what it sounds like: the program frees a chunk of memory and keeps using it, and an attacker who controls what lands there controls what the program does next, which here means running their code as whoever opened the file.

The detail worth your attention is in Microsoft's own advisory FAQ, which answers plainly that yes, the preview pane is an attack vector. A crafted presentation attached to an email can trigger the flaw when the preview pane renders it. Nobody has to double-click the attachment, which means the safety advice most people have internalized does not cover this case. That is why it is worth telling your team about rather than quietly patching in the background.

One practical note that catches people out: Office updates do not ride the Windows cumulative update. They ship on their own Click-to-Run channel, so a machine can be fully current on Windows and still be running vulnerable Office. Verify Office builds separately, and until they are current everywhere, turning off the reading pane for external mail is a reasonable short-term control you can push centrally.

The server side: DNS, Remote Desktop, Hyper-V, Exchange, SharePoint

If you run anything on-premises, this sets your maintenance window.

  • CVE-2026-69730: Windows DNS Server RCE, CVSS 9.8, Critical. A use-after-free reachable by an unauthenticated attacker sending a crafted packet, no user interaction, rated exploitation more likely. The Zero Day Initiative calls it the spiritual successor to SigRed, the 2020 wormable DNS flaw. On most small networks the DNS role runs on the domain controller, making this a patch-the-DC-now item.
  • CVE-2026-69525: Remote Desktop Services RCE, CVSS 9.8. Another use-after-free, also unauthenticated with no user interaction, also rated exploitation more likely. Microsoft labels it Important despite the score, a reminder that the severity label and the CVSS number are two different judgments. If you have Remote Desktop reachable from the internet, this is your emergency, and the reason we keep arguing against that setup in the exposed RDP post.
  • CVE-2026-80083: Hyper-V guest-to-host RCE, CVSS 8.8, Critical. An untrusted pointer dereference that lets code inside a guest virtual machine execute on the host, so a compromise of the least important guest becomes a compromise of everything on that box.
  • CVE-2026-66302: Skype for Business Server RCE, CVSS 9.8, Critical. An unauthenticated attacker can write a file of their choosing anywhere on the server. If one is still racked because nobody turned it off, this month is the reason to finish that project.
  • Exchange and SharePoint. On-premises Exchange gets CVE-2026-55007 (CVSS 8.1), a double-free an unauthenticated attacker can reach by mailing a crafted Visio attachment the server indexes, though it needs the server under sustained memory pressure. SharePoint Server gets CVE-2026-69465 (CVSS 8.8), which needs an authenticated user with page-edit rights, so it is a stolen-credential path rather than a front-door one. Online versions are patched server-side; the case against self-hosting either is in the May SharePoint post.
  • The two perfect tens. CVE-2026-70352 in Azure AI Language and CVE-2026-83711 in Azure AD B2C are both CVSS 10.0 and will top any list sorted by score. Both were mitigated by Microsoft service-side and need no customer action.

KB numbers, builds, and the Windows 10 question

The numbers to verify after deployment, per Microsoft's update history pages. Windows 11 24H2 and 25H2 take KB5124008 (builds 26100.9445 and 26200.9445, servicing stack update KB5124007). Windows 11 23H2 takes KB5122880 (Microsoft lists OS build 22621.7582, servicing stack update KB5122879), and Windows 11 26H1 takes KB5124012 (build 28000.2954). On the server side, Windows Server 2025 takes KB5122871 (build 26100.33438, servicing stack update KB5122870), Windows Server 2022 takes KB5122882 (build 20348.5622), and Windows Server 2019 takes KB5122876 (build 17763.9245). Microsoft lists no known issues against the Windows 11 and Windows 10 packages at release.

Windows 10 21H2 and 22H2 take KB5122878 (builds 19045.7725 and 19044.7725), and only on devices enrolled in Extended Security Updates. This ninth ESU release also fixes an issue that could force devices with an unrecommended BitLocker Group Policy configuration to enter their recovery key, the kind of bug that turns a Tuesday into a very long Tuesday across a laptop fleet, and an issue where Remote Desktop audio redirection would not play a remote session's audio locally.

Microsoft has extended ESU enrollment through October 12, 2027. That is a real reprieve, and a trap if you treat it as a plan: a Windows 10 machine outside ESU got nothing from this release, both exploited zero-days included, and falls further behind every month. Know which of your machines are enrolled, this week. The Windows 10 end-of-life post lays out the exit paths.

Secure Boot: the certificate clock is still running

This month's update widens automatic Secure Boot certificate targeting to more eligible devices, continuing a rollout that has run all year. The deadline behind it has not moved. The Microsoft Windows Production PCA 2011 certificate, which signs the Windows bootloader itself, expires October 19, 2026. The Microsoft Corporation UEFI CA 2011 expired June 27, 2026, and the KEK CA 2011 expired June 24, 2026. Nothing dramatic happens on expiry day: machines still boot and people still work. What you lose is the ability to receive new boot-path security mitigations. Let the certificate updates deploy, then verify status rather than assume it took, mechanics we walked through in the June post.

Two other clocks worth a calendar entry. October's Patch Tuesday brings the final Extended Security Updates for Windows Server 2012 and 2012 R2, and the final ESU for Exchange Server 2016 and 2019. Windows Server 2022 also leaves mainstream support on October 13, 2026. If any of those are still running, the runway is measured in weeks.

How a managed deployment actually works

We do not push a release like this to production machines on Tuesday afternoon, and that is deliberate. Patches occasionally break things, and when they do the industry finds out within a day or two as millions of machines install them and telemetry rolls in. That matters more at 966 CVEs than at 400, because a release this large gives a regression more places to hide. A roughly 48-hour soak costs attackers little of the window that matters and has saved our clients from more than one bad patch Microsoft had to pull and reissue.

So updates go out in rings, which just means groups in a planned order. Our own machines and a small test group take the release first. Client workstations follow in an after-hours window once telemetry is clean. Servers deploy separately in a maintenance window, when a reboot cannot take down file shares in the middle of an invoice run. Two actively exploited zero-days compress that timeline: the soak is a default, not a dogma. And because a patch downloaded but not rebooted into place is protecting nothing, the RMM verifies per machine afterward that the update applied and the build number moved. That verification is the difference between patching as a policy and patching as a hope, the same discipline covered in the patch management post.

How to prioritize this week

If you run your own patching, in order:

  • Install and reboot, everywhere. The cumulative update covers both exploited zero-days at once. Confirm the reboot happened, not just the download.
  • DNS servers and Remote Desktop Services hosts next. Both take unauthenticated CVSS 9.8 fixes, and on a small network the DNS role usually lives on the domain controller, so that box goes first.
  • Hyper-V hosts after that, then on-premises Exchange and SharePoint. If either is reachable from the internet, move it up.
  • Then Office clients, for the PowerPoint flaw. Office rides its own release channel, so a fully patched Windows machine can still run vulnerable Office.
  • Audit Windows 10 ESU enrollment. Either a machine is enrolled and took KB5122878, or it is unprotected against everything in this release.
  • Then the non-patch item. Remove local administrator rights from everyday accounts that do not need them. Both zero-days exist to escalate privilege, and starting from fewer privileges keeps working after the next one drops.
  • Verify, do not assume. Spot-check build numbers (26100.9445 or 26200.9445 on Windows 11, 19045.7725 on ESU Windows 10) rather than trusting the green checkmark.

FAQs about the September 2026 Patch Tuesday

How many vulnerabilities did the September 2026 Patch Tuesday fix?

Microsoft's September 8, 2026 release fixes 966 vulnerabilities by BleepingComputer's count, which tallies only the CVEs Microsoft published on release day. That makes it the largest Patch Tuesday on record, roughly 2.4 times August's 400 and well past July's previous record of 570. By class it breaks down as 438 elevation-of-privilege, 258 remote-code-execution, 173 information-disclosure, 56 denial-of-service, 19 security-feature-bypass, and 16 spoofing flaws, with 105 rated Critical: 81 remote code execution, 20 elevation of privilege, 2 information disclosure, and 1 security feature bypass. Other outlets count differently: the Zero Day Initiative tallies 972 new CVEs with 114 Critical, SecurityWeek reports 974, several outlets land on 973 with 113 Critical, and Action1 counts 995 with 121 Critical.

What are the two zero-days in the September 2026 Patch Tuesday, and how worried should a small business be?

Both are local elevation-of-privilege flaws, both CVSS 7.8, both rated Important rather than Critical, and Microsoft confirms both are being exploited in the wild while listing neither as publicly disclosed. CVE-2026-85880 is a heap-based buffer overflow in Windows Advanced Local Procedure Call that lets code running in a low-privilege AppContainer sandbox escape to SYSTEM with no user interaction. CVE-2026-81963 is an improper link resolution (link following) flaw in the Windows Update Stack that also elevates a local user to SYSTEM. Neither gives an attacker a way into your network. Both are what an attacker uses once already on a machine, which is why installing the cumulative update and rebooting is the fix, and why identity hygiene and endpoint detection stop the step before it.

Why does a privilege escalation flaw matter if the attacker already needs access?

Because getting a foothold is the easy part of a modern attack, and it usually comes from a phished password, a malicious document, or a stolen session token rather than a remote exploit. What separates a contained incident from a business-ending one is whether the attacker can promote that foothold to SYSTEM or domain administrator, because that is the privilege level needed to disable security tooling, reach every file share, and deploy ransomware across the network. A privilege escalation zero-day removes the hardest step in that chain. The defenses that matter alongside the patch are the ones that make both steps harder: phishing-resistant multi-factor authentication, no day-to-day local administrator rights, and managed detection and response with a 24/7 SOC watching for the escalation attempt.

What is the PowerPoint vulnerability, and can the Outlook preview pane trigger it?

CVE-2026-69678 is a use-after-free flaw in Microsoft PowerPoint rated Critical at CVSS 8.8. Microsoft's own advisory FAQ confirms that the Preview Pane is an attack vector, which means a crafted presentation can trigger code execution when it is rendered in the preview pane, without anyone opening the attachment. It was not exploited or publicly disclosed at release, but it is the one item this month where what a person does or does not click changes the outcome. Office updates ship on their own Click-to-Run channel rather than through the Windows cumulative update, so verify Office separately from Windows Update, and consider disabling the reading pane for external mail while patches roll out.

We still have Windows 10 machines. Did we get any of these fixes?

Only if those machines are enrolled in Extended Security Updates. This month's Windows 10 fix, KB5122878 (builds 19045.7725 for 22H2 and 19044.7725 for 21H2), is the ninth ESU release and shipped only to enrolled devices. It also fixes an issue that could force a BitLocker recovery key prompt on devices with an unrecommended BitLocker Group Policy configuration, and an issue where Remote Desktop audio redirection failed to play a remote session's audio locally. Microsoft lists no known issues against the package at release. A Windows 10 machine without ESU received nothing from this release, both exploited zero-days included. Microsoft has extended ESU enrollment through October 12, 2027, so it is still available as a bridge, but it is a bridge, not a destination.

What order should a small business patch in this month?

Install this month's cumulative update and reboot everywhere first, because that single step covers both exploited zero-days. If some machines have to queue: Windows servers running the DNS role or Remote Desktop Services next (CVE-2026-69730 and CVE-2026-69525 are both unauthenticated CVSS 9.8 remote code execution with no user interaction), then Hyper-V hosts (CVE-2026-80083 is a guest-to-host escape), then on-premises Exchange and SharePoint, then Office clients for the PowerPoint preview-pane flaw, then audit Windows 10 ESU enrollment. Verify build numbers afterward: Windows 11 24H2 and 25H2 should land on 26100.9445 or 26200.9445, and ESU-enrolled Windows 10 on 19045.7725, because an installed-but-not-rebooted patch protects nothing.
